# 分级操作指导（2024数证杯实战版）

> 依据：2024数证杯 117 题实战 + 12 题复现验证（见 run notes/TOOL-VERIFICATION.md）+ 火眼 CLI 实测。
> 目的：让所长、民警、辅警、警械每一级知道自己**只做什么、不做什么**。

---

## 零、开跑前能力自检（所长 10 分钟）

| 检查 | 命令/判据 |
|---|---|
| 火眼 APP 分析 | `thunder-app-cli health` → `status:ok, api_version:v3` |
| 火眼数据库 | `Select-String master.log 'master server at 127.0.0.1:(\d+)'` 拿到端口；`app/options` 返回 200 即已授权 |
| 火眼证据分析 | `ges.exe --help` |
| 火眼仿真 | `bootmagix-cli.exe --help` |
| 网钜 | `wmx.cmd status` |
| 模拟器 + frida | `adb devices` 有 emulator；`frida-ps -U` 有进程 |
| VC | `vc.ps1 state` + 一次只读挂载（耗时 <1 秒作废） |
| TSK | `fls/mmls/fsstat/istat` 可用 |
| WSL | `ibd2sdi/mysqld/ewfmount/binwalk/foremost` 命中 |
| 判定 | 结论写进每个 brief：哪些分支能深挖、哪些只能扫描级 |

**没设备/没工具的分支，开跑就放弃，不派人力**（本轮 程序13–16 的 40 分就是这样省下来的）。

---

## 一、所长（0 级）：只做四件事

1. **受理与建网**：案名、检材、题单、时限；`cn init` + `cn scan`；分配 ID。
2. **派活**：一个分支一个民警；民警按"题目关联簇"派辅警；**每个 brief 必须带**：分支题数、可用时间、工具自检结论、必须写回的字段。
3. **巡检（每 10 分钟，三看三决定）**：
   - 看 `cn where`：谁卡住、谁 15 分钟没动；
   - 看 `cn stat`：已定/候选/insufficient 数量对不对；
   - 看时间：>60% 预算还没出第一版结果的分支，立刻降级。
4. **复核与收口**：见第四节。

**所长禁止**：自己下场做题；凭印象报数字；用官方答案/题解填答案。

---

## 二、民警（1 级）：按分支选工具链

| 分支 | 首选工具链 | 关键一跳 |
|---|---|---|
| 计算机取证 | pyewf→pytsk3→pyvhdi→dissect；**pagefile.sys 按 UTF-16LE 搜** | 宝塔账号密码在 pagefile 内存残留，不在 default.db |
| 服务器取证 | jar 里 `application-*.yaml` + **WSL `ibd2sdi` 拿表结构** + `mysqld --innodb-force-recovery=6` 只读实例 | 金额自洽：sum(借款)−sum(服务费)=sum(打款) |
| 手机取证 | `/data/user_de/0/` 真库；`packages.xml` ft/ut；DCIM 截图找密码 | mmkv 里常藏关键 JSON |
| 网络流量 | `tshark -q -z io,phs`、`--export-objects http,<dir>` | pcapng 文件头 option 有抓包机信息 |
| 程序功能分析（APK） | **火眼 APPAnalysis 全链路**（见下） | 360加固必须先脱壳；模拟器可静态/反编译，脱壳需真机 |
| 数据分析 | VC 挂载（`.lnk` 做 keyfile）→ 块设备整卷读出 → TSK | 微信账单 pdfplumber；赌博库 SQL |

### APK 分支标准动作（已实测）

```powershell
$cli='E:\存档\Forensix\APPAnalysis\skills\bin\thunder-app-cli.exe'
& $cli case create --name <案名> --case-path E:\forensix-cases
& $cli evidence add --cid <cid> --file <apk> --name <检材>
& $cli analysis detail/permissions/third-party --cid <cid> --aid <aid>
& $cli source decompile --cid <cid> --aid <aid> --timeout 15m
```

- 权限/第三方 SDK/反编译产物直接落地，**民警只写结论与定位**；
- 脱壳：`unpack start` 预检 360 通过后仍需真机；没有真机时**用模拟器 + frida 手工 dump dex**，或判 `insufficient` 并写明原因。

### 民警的审注记（辅警交回时必须查）

`cn see` 的三要素：**结论 + 说明 + 定位**，缺一打回；没有来源路径的结论不接受。

---

## 三、辅警（2 级）：只做"单点取数"

- 一题一辅警；强关联题打包给一个。
- 每个辅警只回答一个问题，必须写回：`值 + 来源路径 + 定位`。
- 允许的命令：`catalog`、`schema`、`rows`、`query`（只读 SQL）、`ai-sql`、`grep`、`wmx table`、`ges.exe read/grep`。
- 遇到密码：`cn task block` 报 blocked，**不许爆破**；民警收到后 5 分钟内派破译者。
- 不许自己改题号、不许"顺手"回答别的题。

---

## 四、警械（3 级）：一条命令，一个动作

- 只执行民警/辅警给的具体命令，不判断、不改参数、不换工具。
- 输出原样回传（含报错）；报错不吞。
- 典型命令：`thunder-app-cli case list`、`database-search-cli --master-port <p> catalog --sid <s>`、`wmx status`、`fsstat -f fat <img>`、`icat -o <off> <img> <ino>`。

---

## 五、复核（所长收口前必做）

| 复核项 | 做法 |
|---|---|
| 口径 | 按题面措辞选（连接/共享名/渠道数/总计） |
| 候选必交 | 有值就交，标低置信度；insufficient 只留给零线索 |
| 格式 | 严格照题面示例，不多不少 |
| 聚合绑题号 | (SQL 口径, 数值, 题号) 三元组排一遍 |
| 交叉验证 | 同一结论用**第二个独立工具**再算一遍（火眼 CLI vs 我们的 python） |
| 反解 | 起始扇区 + 保留 + FAT 大小 = 数据区起始 |
| 串号 | 提交前逐条确认"这个结果属于哪个文件/题" |

## 六、本轮验证过的"关键方法"（可直接复用，不是答案）

1. **pagefile.sys 按 UTF-16LE 搜**：宝塔账号/密码在内存残留里。
2. **U 盘 FAT 参数**：全盘搜扇区对齐的 `F8 FF FF 0F`，命中位置即 FAT1 起始；`起始+保留+FAT大小=数据区`自洽。
3. **keyfile 可以是任意文件**：`.lnk`、文档、空文件都行；VC 挂载后按块设备整卷读出再用 TSK 取簇（`fsutil` 对 VC 卷无效）。
4. **钱包派生**：助记词 → `eth_account` 派生地址/私钥；BTC ≠ MetaMask。
5. **官方口径可能反直觉**：如 `loginTime <= '2020-06-30'` 是字符串比较（排除 6/30 全天），按语义算会多 9 人。
6. **隐写**：图片先 `binwalk`，RAR/PNG 内嵌要按偏移解。
7. **工具自检结论直接决定人力**：没 frida/没真机，程序 13–16 直接放弃。

## 七、仍做不了 / 不要浪费人力

| 题 | 原因 | 处置 |
|---|---|---|
| 程序 13–16 | 360加固，脱壳需真机（模拟器被火眼拒） | 有真机再派；否则 `insufficient` 并写清三问 |
| 程序 4–7 | 纯逆向深度（x64dbg 跟 52 次循环） | 派最强 1 人限时 15 分钟，无进展即放弃 |
| 数据分析-4 | 没定位到密码文件 | 全盘按"密码"语义搜 prefs/mmkv/keyvalue，仍无则 `insufficient` |

## 作答口径（所有层级通用，2025-11 复盘后加入）

1. **格式写死**：单选只写字母；多选英文逗号升序（B,C,D）；判断写「对/错」；填空只写值本身。
2. **主语规则**：题面有「此/该/这个/以上」时，先锁定主语实体（文件本体 vs 内部卷、本机 vs 对端、发送 vs 接收），再套证据。
3. **长串校验**：哈希/地址/邮箱/群 ID 提交前核对长度与首尾，禁止省略号。
4. **候选收敛**：主攻过半即启动，按「题面主语 + 平台口径」双口径，主值取检材原文，定位列记另一口径。
5. **复核专线**：只看题面逐字措辞与选项主语，不看证据自洽；每题给一行「按另一口径会是什么」。
6. **官方答案可能有笔误**：照抄题面/平台口径优先，定位列同时留两种写法。

## 并发与资源纪律（2025-11 美亚杯团体赛卡死复盘后加入）

1. **开场先报看板**：所长受理后立刻 & C:\dsh-forensic\start-board.ps1，并在第一条消息报地址 http://127.0.0.1:8766/ 、run-id、题数、时限。
2. **并发上限**：全局活跃子代理 ≤12；民警 ≤5；单个民警同时 ≤2 个辅警。
3. **重工具串行**：解压 / E01 解析 / jadx / 大文件扫描一律用 50-scripts\heavy.ps1 -Name <名字> -Cmd "<命令>" 包裹（排队锁 + 低优先级）。
4. **解压一次复用**：extracts/<检材>/ 写 _DONE 后复用，禁止重复解压、禁止大文件读进内存。
5. **卡顿应急**：用户说卡 → 停止派活、停在跑重工具、活跃降到 4，先让民警把已得答案写 ans.mjs。

## 编成与调度（容量规划，2025-11-14 加入）

- 活跃预算 16：民警 ≤6、单民警辅警 ≤2、**预留 ≥2 槽**。
- 初始只派"底仓"：题量 ≤40 → 民警 2–3 各带 1 辅警；41–120 → 民警 3–4；121–260 → 民警 6（各 1 辅警）；>260 → 先 3 民警各 1 辅警，稳定后再放行。
- 民警 brief 写死："先带 1 个辅警，等所长放行再加"。
- 每 10 分钟调度节拍：数活跃（心跳 15 分钟内）+ 积压（未认领 task + 未答题）→
  - 放行：活跃 ≤10 且积压 >10 → +1 辅警或 +1 民警，一次最多 2 个；
  - 降档：活跃 ≥11 或用户报卡或内存 <3GB → 停派活、降重工具、等完成到 4；
  - 维持：其余不动。决策 cn anchor 留痕。
- 放行优先级：零人分支 > 积压最多民警 > 候选收敛专线；有 agent 完成即释放槽位，下个节拍可补。

## 所长如何判断"资源到上限"（2025-11-14 加入）

每 10 分钟一次，两条命令定量：
1. list_agents → 数 status=running，得到**精确活跃数**（上限 12）；
2. & 50-scripts\sysgauge.ps1 -Json → 一次拿到 cpu_pct / ram_free_gb / disk_queue / heavy_lock / state / recommend_slots。

健康线（同时满足才继续加人）：
- 空闲内存 ≥ 6 GB（系统保留 4 GB）
- CPU 5 秒平均 < 70%
- 磁盘队列 < 2
- heavy_lock = false（没有重工具在排队）

决策公式：
- 可放行数 = min(recommend_slots, 12-active, 2)，且积压 > 10 → 放行，放完 2 分钟复测；
- 任意一项越线（内存 <4GB / CPU >90% / 磁盘队列 >3）→ 降档到 4，停派活、停重工具；
- 中间地带 = HOLD，只观察不新增。

"尽可能利用"：state=UP 就一直加到 12（或 RAM 允许的 recommend_slots），不是低负载就好；只有越线才降。

## 题型易错清单（2025-11 团体赛判分复盘）

1. 填空写完整：版本串带厂商/型号（DELL - 1072009 1.29.3 American）、工具全名（ServerMonitor.exe）、端口/DB 版本原样、MAC 六段、哈希/地址不截断。
2. 选择题先判断题干问"字母"还是"内容"；多选逗号升序；"以上皆非/皆是"逐项对齐主语。
3. 时间戳精确到秒；恢复工具带 -m 保留原 mtime；年月日不许颠倒。
4. 数值先确认口径（总量/当前/增量、单位）；URL 编码还原；同类文件按题干选。
5. 缺失检材先确认归属，确缺也给候选值并注明缺件，绝不留空（空值 = 0 分）。
